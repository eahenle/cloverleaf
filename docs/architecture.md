# Cloverleaf architecture

Cloverleaf is a local-first two-process application managed by a small launcher. A Vite/React frontend provides the writing environment; a FastAPI backend owns all filesystem, compilation, runtime-control, and AI-provider access. Manuscript files live under one configured workspace root and are never mixed with application source.

## Components

- **Frontend (`frontend/`)**: React, TypeScript, CodeMirror 6, `react-resizable-panels`, and PDF.js. It uses JSON APIs, debounces saves and compilation requests independently, and polls short-lived compile status. PDF pages render to canvases and retain their approximate scroll position across successful recompiles.
- **Backend (`backend/cloverleaf/`)**: FastAPI routes delegate to small services. `Workspace` resolves and validates every user path beneath the configured workspace. `Compiler` coalesces and serializes `latexmk` jobs, parses common LaTeX diagnostics, and exposes the latest successful PDF. `LocalGitRepository` initializes and checkpoints the active project without remote access. `ProjectSync` runs configured shared-repository synchronization in a background thread, discovering sibling projects and registering new/loaded roots persistently. Its own clone stores each project under `projects/<name>/`, uses content baselines to import cloud changes and publish local changes, and reports conflicts without overwriting either version. See [project sync](project-sync.md). `AssistantProvider` isolates Codex behind a read-only SDK adapter; an OpenAI-compatible adapter remains available as a fallback.
- **Launcher (`scripts/dev.py`)**: supervises backend and frontend process groups with no terminal input, combines their stdout/stderr into a tagged 1 MB rotating log, and owns restart and shutdown lifecycles. A restart stops and recreates both child groups while retaining the supervisor lock and runtime identity. The root entry point detaches this supervisor; `make dev` keeps only the supervisor in the foreground. Development reload shutdown is bounded so persistent file/log WebSockets cannot indefinitely prevent a changed backend from restarting.
- **Workspace (`workspace/`)**: the default manuscript project. `main.tex` is the configurable compilation root.

The active workspace can be replaced at runtime through the project-load endpoint. A directory-browsing endpoint supplies the in-app folder picker with readable, non-hidden folders and direct `.tex` candidates; it does not return file contents. A folder without a direct `.tex` candidate receives a minimal `main.tex` as part of the confirmed load. A switch otherwise accepts only an existing absolute directory and an existing relative `.tex` compilation root. The backend finishes the current build, persists the selection in an ignored local state file, constructs a new `Workspace`, `Compiler`, and project-root `LocalGitRepository`, rebinds Codex to the same working directory, and then exposes the new project atomically. Startup restores a still-valid saved selection, including after development reloads, without rewriting `.env`. Assistant turns also verify Codex's working directory against the authoritative backend workspace before starting.

Repository initialization is local-only. A project without `.git` receives a repository and an initial snapshot; an existing unborn repository receives the same baseline, while a repository with a commit is left untouched on activation. Confirmed creates, writes, renames, deletes, and multi-file assistant applies stage and commit only their affected paths, preserving unrelated work and staged changes. Repository-specific LaTeX artifact and `.cloverleaf/` internal-state exclusions live in `.git/info/exclude`, and `/api/project/git` exposes initialization, current HEAD, and the most recent checkpoint error without turning a Git failure into a failed file save.

Within the active project, an open `.tex` file can become the compilation root through a narrower endpoint that preserves the workspace and Codex working directory. The backend validates and persists the relative source path, finishes an in-flight build, replaces the compiler, and exposes the selected root as authoritative assistant context. Nested roots give `latexmk` their source directory as its output directory, keeping auxiliary files and the PDF beside the source while retaining the project root as the process working directory. The frontend keys its preview by both workspace and compilation root so output from the previous view is cleared before the selected view's successful PDF is rendered. Saving that rendered revision uses the browser's native file-save picker when available and a standard download fallback otherwise.

The new-project endpoint accepts an existing absolute root or one visible child-directory name to create beneath an existing parent. It initializes a minimal `main.tex` only when that file does not already exist, then uses the same persisted workspace, compiler, and assistant rebinding lifecycle as project loading.

## API and trust boundary

The browser never receives provider secrets and never accesses the host filesystem directly. File routes accept UTF-8 files inside the active project, including hidden configuration and skill files, while rejecting relative traversal, Windows absolute paths, symlink escapes, and `.git` internals. Generated LaTeX artifacts remain hidden from the tree but can be addressed directly when they are genuinely project content. Compilation invokes a fixed executable with a fixed argument list from the workspace directory, without a shell or shell escape.

When the launcher is present, it passes FastAPI absolute paths for its runtime log plus private restart and shutdown sentinels. FastAPI can stream the bounded log, but it does not expose a terminal or arbitrary process signaling. Confirmed lifecycle requests write only the corresponding sentinel; the supervisor remains responsible for recycling or terminating its own child process groups. The browser log client reconnects across a managed restart. Direct backend launches have none of these paths and therefore expose no logs and reject both controls. `/api/status` separately aggregates configuration and live state for the API, project, Git repository, compiler, assistant provider, and launcher; the Status tab adds its own frontend heartbeat and refreshes the report periodically.

Codex runs server-side with the SDK's read-only sandbox preset and the active project as its working directory. SDK-level developer instructions establish its standing LaTeX-authoring objective and require change requests to produce concrete edits rather than suggested replacement text in the conversation. Per-turn context supplies the authoritative compilation root plus the active build state, bounded log tail, open file, selection, and structured diagnostics; other files are discovered agentically with read-only runtime tools.

The Compiler panel's failure action is a frontend shortcut into this same assistant flow. It submits a focused repair request, brings the Codex conversation forward, and relies on the backend's authoritative compile context; suggested repairs retain the ordinary review and confirmation boundary.

The SDK enforces a structured response with separate message and compact exact-replacement fields. FastAPI normalizes absolute in-project targets to canonical relative paths, requires each existing-file match to be unique, expands replacements in order into complete review content, and attaches the current file version before returning a review card. Any UTF-8 project file is supported. A target outside the active root or inside `.git` becomes a structured warning and is omitted without discarding other valid proposals from the same turn; malformed in-project replacements still fail atomically. Only Cloverleaf's explicit, confirmed apply flow can write an edit. Multiple accepted cards are written together, committed as one checkpoint, and trigger one compilation. Each assistant POST has a short-lived, request-scoped WebSocket: FastAPI translates selected SDK turn/item/retry events into stable non-sensitive phases and emits a heartbeat during quiet periods while the ordinary JSON request retains normal success and error semantics. Raw reasoning, command text, tool arguments, and credentials remain server-side.

The frontend serializes assistant rounds. A prompt submitted during an active request is retained in an ordered client-side queue and displayed below the active runtime status; it is not included in the in-flight request. After a response without edits, or a contained error, is appended to the transcript, the oldest queued prompt becomes the next user message and starts with the complete updated conversation. A response with reviewable edits instead installs a review barrier: new prompts remain queued until every card from that response is applied or dismissed, then the queue resumes automatically. This prevents the next assistant request from holding the project lock while the user tries to apply the preceding edits. Additional prompts drain one round at a time, and the project cannot switch until the queue is empty. Each active request is also registered as a backend task by its progress-channel UUID. Cancellation marks the request, cancels that task, invokes the SDK turn-interrupt method, aborts the browser fetch, and clears the client queue; the project lock is released by normal task unwinding.

The project-scoped `GET` and `PUT /api/project/codex-history` routes persist the transcript and dismissed edit-card keys in `.cloverleaf/codex-history.json` beneath the active workspace. Writes validate the request's workspace, enforce a bounded payload, and replace the JSON file atomically. The frontend serializes its save requests and restores this state during startup and project switching, deriving any pending review barrier from the saved transcript. `.cloverleaf/` is hidden from the project tree and excluded through the repository-local Git rules, so conversational UI state survives process restarts without becoming a manuscript checkpoint.

The app binds to localhost by default. This MVP assumes a trusted manuscript and does not claim to sandbox TeX itself.

## Extension seams

`AssistantProvider.chat(messages, context)` can be replaced without changing API consumers. Future project tools can be implemented behind a tool executor while preserving the route and response models. A future project registry can construct one `Workspace` and `Compiler` per selected root without changing their invariants.
